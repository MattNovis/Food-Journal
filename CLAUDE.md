# Kin Khao: Thailand food journal

Matt sends a photo + a quick description of something he ate. Turn it into a journal entry, then
republish the artifact. Keep the reply short: confirm what was logged, and ask only about things that are truly missing.

Read PRODUCT.md for the brief and DESIGN.md for the brand kit (tokens live in `site/brand.css`).
The design skill is vendored at `.claude/skills/impeccable`. Use it for any UI change.

## Layout

```
data/trip.json      itinerary snapshot from atlas-trip-studio (scripts/sync_trip.py) — don't hand-edit
data/entries.json   THE journal: one object per dish
photos/             web-sized JPEGs, metadata stripped (scripts/add_photo.py)
site/index.html     the journal page    site/brand.html  brand kit    site/brand.css  tokens
site/data.js        generated by scripts/build.py — never hand-edit
```

## Adding an entry (every time)

1. **Photo → disk.** If the image came in as an attachment with a file path, use it. If it only exists
   inline in the chat and there is no file to copy, say so and ask Matt to send it another way
   (Drive or GitHub upload). Never fake or regenerate a photo.
2. `python3 scripts/add_photo.py <src> <date>-<dish-slug>` → prints the path, size, EXIF time and GPS.
   Use the EXIF date/GPS to fill `date`/`time` when Matt doesn't give them. The GPS is NOT published (it's stripped).
3. Append to `data/entries.json`:
   ```json
   {
     "id": "2026-11-24-khao-soi",
     "date": "2026-11-24",              // trip day (Bangkok time); defaults to today in Asia/Bangkok
     "time": "19:30",                    // optional
     "meal": "dinner",                   // breakfast|lunch|dinner|snack|dessert|drink
     "dish": "Khao soi gai",
     "thaiName": "ข้าวซอยไก่",            // add if you're confident; otherwise omit
     "description": "Matt's words about the MAIN dish, lightly tidied — keep his voice, don't embellish",
     "place": { "name": "Khao Soi Mae Sai", "area": "Nimman, Chiang Mai", "mapsUrl": "https://maps.google.com/?q=..." },
     "priceThb": 60,                     // number; convert other currencies and note it in priceNote
     "priceNote": "for two",             // optional
     "scores": {                         // the rubric — each question 1.0–10.0, one decimal
       "main":  { "flavour": 9, "value": 7, "texture": 9, "presentation": 7 }
     },
     "ambiance": 4,                      // 1–10, the setting; NEVER part of the food score
     "sides": {                          // optional — everything else on the table
       "rating": 6,                      // ONE overall 1–10 for all the sides (Matt gives it directly)
       "items": [                        // plain names, or objects for noteworthy sides
         "Milk tea",
         { "name": "Smashed cucumbers", "rating": 7, "note": "fresh" },
         { "name": "Hot cabbage", "rating": 4 }
       ],
       "note": "His comments on the sides"
     },
     // "rating" (main) is COMPUTED by build.py from scores.main — don't type it.
     "region": "chiang-mai",             // optional — defaults from data/trip.json for that date
     "photos": [{ "src": "photos/2026-11-24-khao-soi.jpg", "w": 1200, "h": 1600, "alt": "Bowl of khao soi..." }]
   }
   ```
   Region keys: transit, bangkok, chiang-mai, chiang-rai, doi-inthanon, koh-lanta.
   On travel days (e.g. "Bangkok → Chiang Mai") set `region` to where the food was actually eaten.
4. `python3 scripts/build.py` (validates + writes `site/data.js`).
5. Commit (`Add <dish> (<date>)`) and push to the working branch.
6. Republish the artifact: Artifact publish with `file_path: site/index.html`, and a `files` map adding
   `data.js` and the new `photos/<name>.jpg` (existing files are kept). Use the same artifact URL as before
   (recorded below).

### Scores entered on the page (artifact db)

Matt can score dishes on the page itself (open a dish → Score it). Those land in the artifact's db,
collection `scores`, one doc per entry id:
`{ main: {flavour, value, texture, presentation}, sidesRating, sideItems: {"<side name>": n}, ambiance, updatedAt }`.
The page shows db scores over the repo data. **Before every entry update**, read them with the
`ArtifactData` tool (`list`, collection `scores`) and fold them into `data/entries.json`:
`main` → `scores.main`, `sidesRating` → `sides.rating`, each `sideItems` value → that side's
`{"name", "rating"}` object, `ambiance` → `ambiance`. Then build. Leave the db docs in place (they match).
Only the owner and editors can write (db rule `write: "admin"`); everyone else just views.
When republishing, OMIT `capabilities` so the stored declaration carries over.

### Scoring rubric

Matt sends: `dumplings 9 7 9 7 / sides 6 (cucumbers 7, cabbage 4) / amb 4`.
Main dish = four numbers in order **Flavour, Value, Texture, Presentation**, each 1.0–10.0
(one decimal allowed, e.g. 8.6 — the page's sliders work in 0.1 steps).
Main score = (Flavour×3 + Value×2 + Texture×2 + Presentation×1) ÷ 8, i.e. Flavour 37.5%, Value 25%,
Texture 25%, Presentation 12.5%. Always describe the weights to Matt as percentages.
Sides = ONE overall 1–10; individual sides get their own score only when he calls them out.
Sides and ambiance are optional. If he sends a single number for the main, ask once for the four.
Anchors: 1–2 bad · 3–4 below par · 5–6 fine/as expected · 7–8 genuinely good · 9–10 among the best.
Ambiance (1–10) is the setting and is shown separately; it never affects food scores.
Old entries with only a plain `rating` are legacy until Matt rescores them.

If a rating, price or place is missing, log the entry anyway and ask once in the reply ("score out of 10?").
